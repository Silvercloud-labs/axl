# FAQ — 常见问题

---

### AXL 是开源的，还是只是免费的？

**开源的。** Apache License 2.0，一个 OSI 批准的许可证。您可以阅读、运行、修改、重新分发、fork 它，以及销售基于它构建的软件 — 商业用途，无需申请，无需付费。

没有开放核心分割，没有付费层，没有遥测，也没有被保留的功能。整个工具链都在这个仓库中：编译器、运行时引擎、CLI、生成器和 VS Code 扩展。

### 为什么选择 Apache 2.0 而不是 MIT？

| | MIT | Apache 2.0 |
|---|---|---|
| 自由使用、修改、销售 | 是 | 是 |
| 明确的专利授权 | 否 | 是 |
| 名称的商标保护 | 否 | 是 |
| 需要声明更改 | 否 | 是 |

### 它已可用于生产环境吗？

**还没有，坦率地说，没有任何东西已经上线。**

| | 状态 |
|---|---|
| 编译器、运行时、CLI | 正常运行，750 个测试通过 |
| 发布到 npm | 否。第一个版本尚未发布 |
| VS Code 扩展上架应用商店 | 否。从源码编译 |
| 在生产中使用过 | 据我们所知，没有 |

### AXL 不做什么？

| 不在范围内 | 原因 |
|---|---|
| 认证、支付、身份基础设施 | 后端职责。AXL 从不发行、存储或验证凭证 |
| OAuth 集成 | 完全由后端负责 |
| 数据库或 ORM | AXL 不持有领域数据 |
| 完整的 MCP 对等 | 无 Prompts、Notifications、Progress tracking 或 Roots |
| 应用代码分析 | `axl adapt` 读取 API 规范，而非源代码 |
| 补偿事务 | 失败的工作流不会回滚已完成的步骤 |

### 我需要重写后端吗？

不需要。AXL 从不替换您的后端 — 它位于后端前面，通过 HTTP 调用它。
