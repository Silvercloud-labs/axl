# FAQ — Часто задаваемые вопросы

---

### AXL с открытым исходным кодом или просто бесплатный?

**С открытым исходным кодом.** Apache License 2.0, лицензия, одобренная OSI. Вы можете читать, запускать, изменять, распространять, форкать и продавать программное обеспечение на его основе — коммерчески, без разрешения и без оплаты.

Никакого разделения на open-core, платных тарифов, телеметрии и скрытых функций. Вся цепочка инструментов находится в этом репозитории.

### Почему Apache 2.0, а не MIT?

| | MIT | Apache 2.0 |
|---|---|---|
| Свободное использование, изменение, продажа | Да | Да |
| Явное патентное разрешение | Нет | Да |
| Защита торговой марки имени | Нет | Да |
| Требует указывать изменения | Нет | Да |

### Готов ли он к продакшену?

**Ещё нет, и честный ответ — ничто ещё не запущено.**

| | Статус |
|---|---|
| Компилятор, runtime, CLI | Работает, 750 тестов пройдено |
| Опубликован на npm | Нет. Первый релиз ещё не выпущен |
| Расширение VS Code в Marketplace | Нет. Соберите из исходников |
| Используется в продакшене | Насколько нам известно, нет |

### Что AXL не делает?

| Вне области | Причина |
|---|---|
| Auth, платежи, идентификация | Ответственность бэкенда. AXL никогда не выдаёт, не хранит и не проверяет учётные данные |
| OAuth-интеграции | Полностью в ответственности бэкенда |
| База данных или ORM | AXL не хранит доменные данные |
| Полное соответствие MCP | Нет Prompts, Notifications, Progress tracking или Roots |
| Анализ исходного кода приложений | `axl adapt` читает спецификации API |
| Компенсирующие транзакции | Неудавшийся воркфлоу не откатывает завершённые шаги |

### Нужно ли переписывать бэкенд?

Нет. AXL никогда не заменяет ваш бэкенд — он стоит перед ним и вызывает его через HTTP.
